# Audit 01 — Alerting core (`sentinel/alerts/`, scheduler call site)

Auditor scope: `sentinel/alerts/state_machine.py`, `dispatcher.py`, `twilio_client.py`, `push_client.py`,
the dispatch/check-pending block of `sentinel/scheduler.py` (`run_cycle` :214-354), and the five alert test files.
Read at master `835ed8e`. Read-only; no repo file was changed.

## How the findings were verified

- The existing alert tests pass: 90 passed (`.venv/bin/pytest tests/test_state_machine.py tests/test_dispatcher.py tests/test_incident_alerts.py tests/test_push_client.py tests/test_twilio_client.py -q`).
- Coverage of `sentinel/alerts` is 90%, but the uncovered lines are the acknowledgement path: `state_machine.py` 589-590, 604-605, 616-617, 623-627, 635-636, 649-659, 706-715, 814-822, and `twilio_client.py` 123-129.
- Eight probe tests in a scratch file (not in the repo) confirmed findings A1, A2, A3, A4, A5, A6, A8 and A9:
  `<audit-scratchpad>/test_probe_alerts.py`
  (run: `PYTHONPATH=. .venv/bin/pytest <that file> -p tests.conftest -q`). All 8 passed, so every bug they assert is real on master.
- Twilio SDK 9.4.5 was read in `.venv`: `TwilioHttpClient(timeout=None)` is the default, and network errors raise `requests` exceptions, not `TwilioRestException`.

Legend: **BP** means behavior-preserving (yes/no). "No" means it changes who gets called or notified, or when, so the owner decides.

### Known TODO items: accuracy check

- **"Unacknowledged calls are retried only when a new article joins the event"**: accurate. It misses the bigger half, which is A4: the reply itself is never read after the round, so even a joining article cannot acknowledge.
- **6.1 #5 "confirmation code stored on bare instance attributes"**: this understates the problem. It is framed as a future concurrency risk only, but the code being in memory, regenerated each round and lost on restart is a **live** defect today (A4). `_confirmation_sms_sid` also stays from the previous event when the next confirmation SMS fails (`:676-677`).
- **"Stale retry_pending calls after a Twilio recharge"**: the line references are correct. "Each match extends that" undercounts, because every alert-status write also bumps `last_updated_at` (A11).
- **"No working out-of-band watchdog"**: it names only `check-health.sh`. The in-process alarm `_check_pipeline_health` → `_send_system_sms` (`scheduler.py:471-477,550-554`) is also Twilio-only, fires only at exactly 3 consecutive failures, and is silent today.
- **6.1 #17 (`--dry-run` polls pending calls)**: accurate (`scheduler.py:304-309`).
- **6.1 #6 dead keys**: accurate. `critical.retry_interval_minutes` is dead, and the retry guard uses `acknowledgment.retry_interval_minutes` (`:566`).

## Proposed phase grouping (alerting core)

1. **Phase A — Tests first (no production change).** Do A13: the live-config golden routing test, acknowledgement-path tests, the 401-shaped failure tests, and the exception-isolation tests, written as xfail for A1–A3. Gate: the suite is green, and the new xfails document the bugs.
2. **Phase B — Never lose the call (behavior-preserving guards).** A1 (push guard), A2 (Twilio timeout and broad catch), A3 (per-event isolation), A7 and A8 (config validation at load), A9 (confirmation summary cap), A5 (keep the acknowledged label). Gate: the Phase A xfails flip to pass. Deploy on its own commit, because these are small, safe and life-safety relevant.
3. **Phase C — Structural split (behavior-preserving).** A12 (module split, `CallRound`, Twilio wrapper methods for inbound SMS), A16, A17 enums (without the new alert types), A18, A19, A14 (config-ised strings with identical defaults), A15 (after the production count query), A22. Gate: all tests are unchanged and green, and the rendered SMS and TwiML are byte-identical in a snapshot.
4. **Phase D — Owner decisions (behavior changes).** A4 (acknowledgement after the round, with a per-event code; best done together with the known Phase-1 retry sweep and the "Stale retry_pending" max-age rule), A6 (pending-record max age), A10 (uncorroborated fallback channel, decided together with the corroboration item), A11 (whether delivery writes extend memory), A20, A23. Then A21 (call rounds outside the cycle lock) last, only after A4 and the fragmentation fix.
