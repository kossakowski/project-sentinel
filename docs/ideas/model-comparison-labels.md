# First 50 model-comparison labels

## Status and scope

- This note documents [`tests/fixtures/model_comparison_first50.yaml`](../../tests/fixtures/model_comparison_first50.yaml). The fixture contains exactly 50 cases: 44 verbatim articles from `data/eval/production-candidates.json` and 6 explicitly synthetic policy contrasts.
- These labels are research annotations for model comparison. They are not independently human-approved ground truth. Forty-five cases are `provisional`; five ambiguous or policy-dependent cases are `disputed`; none are `approved`.
- This annotation pass was offline and made no production, provider/API, notification-transport, or configuration calls. The frozen source snapshot had already been created by the root work through an authorized read-only production export.
- Each production case records the production article UUID and source index. Its title, summary, URL, source metadata, publication time, fetch time, and metadata language are copied exactly from the frozen snapshot.

## Label interpretation

- `relation: new` starts a separate physical incident or content item. `relation: same` requires `same_as`, which points to an earlier case ID in the same chronological sequence. A shared country, weapon, or topic is not enough.
- `notification: initial` means the article should cause the first alert-worthy notification for that incident. `silent` covers low-threat new items and non-escalating duplicates/updates. `update` is reserved for a significant same-incident danger escalation.
- `critical: true` means the independent article severity is in the 9–10 critical tier. It does not by itself mean a duplicate should notify again.
- Urgency is a range because short source summaries do not justify false precision. Affected countries follow the physical-danger text, not the Google News query embedded in `source_name`.
- Cases are replayed in preserved `fetched_at` order. Source timestamps are not shifted. The runner must inject its replay clock for database-window behavior and must never expose later cases to an earlier classification.

## Required human review

- `mc-border-train-02` is disputed because a strike one kilometre from Poland on the same day plausibly matches the train incident, but its title-only evidence omits the train and exact place.
- `mc-lithuania-drone-09` is disputed because the new explosives detail crosses the independent critical threshold. Current safety plumbing treats a first critical report for a previously noncritical incident as an escalation update, while a reviewer may regard this as retrospective detail after the drone was already downed.
- `mc-assassination-02` and `mc-assassination-03` are disputed because the short records plausibly describe the same US disclosure/network, but do not prove that they cover the identical operational case set.
- `mc-synth-location-03` is disputed because the article is a resolution report after the Latvian alert ended. The current annotation uses retrospective urgency 3–4 and `critical: false`; the operator must decide whether reporting the just-intercepted attack drone should instead retain incident-level critical severity.
- The Poland scramble sequence needs policy review at the resident-alert boundary. Cases `mc-scramble-pl-01`, `-03`, and `-06` are critical under the explicit shelter/air-alert rule; the other reports remain 5–6 because they state only precautionary scrambling or closures without a Polish strike.
- The near-border train sequence should be checked against full article bodies if those become available. The current titles and summaries consistently place impacts in Ukraine near Poland, so the labels do not treat Poland as attacked.

## Caveats

- Many Google News rows contain only a title repeated as the summary. Identity and severity labels use only those available facts and do not fill gaps from outside knowledge.
- Publication and fetch times are evidence order, not proof of incident time. Later publication can describe an older incident. Explicit source wording about a new wave, different location, or ended prior event controls instead.
- `article.language` is input metadata and is never corrected. `mc-warsaw-airport-01`, `mc-belarus-drills-01`, and `mc-assassination-01` deliberately preserve `language: uk` although their Telegram text is Russian; provenance records `content_language: ru` and the mismatch.
- Synthetic cases are difficulty contrasts, not claims about real events. Their `synthetic://` URLs, `source_type: synthetic`, and provenance purpose make them mechanically distinguishable.
- The older `eval_set_human.yaml` includes malformed IDs and placeholder or nonsensical `event_type` values. Those fields were not copied. The first-round schema has no expected `event_type`; adding an event-type score later requires a fresh, explicit annotation pass rather than treating template values as truth.
- `same_as` identifies the expected earlier incident anchor. A runner must score a merge to the wrong old event as an identity error even if it predicted the generic relation `same`.
- Some low-tier or non-military anchor stories never create a runtime Event. For their later `same_as` cases, the runner must mark incident identity unscorable when the anchor Event is absent; it must not punish the model for failing to return an event ID that cannot exist.
- Holdout cases must remain hidden until evaluation. No report should describe the fixture as approved release-gate data while any label remains provisional or disputed.

## Review decision record

- Promote a case to `approved` only after a named operator reviews the source evidence, urgency range, country, notification, relation, and `same_as` anchor.
- If review cannot resolve incident identity from title/summary, keep the case `disputed`; do not force it into a release gate.
- When a source body changes the physical location, incident time, or presence of an offensive weapon, update both the fixture rationale and this inventory together.
